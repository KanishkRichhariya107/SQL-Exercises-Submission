(Scan type)-  Seq Scan, Index Scan, Index Only Scan
(on table)- the table that is being scanned
(cost=a..b)- a is startup cost, b is total cost
(rows) - Estimated number of rows returned by that node
(filter)- condition that is applied to the rows

4.1

Explain 
Select c.*
from comments as c
inner join users as u
on c.user_id = u.user_id ;

                              QUERY PLAN                              
----------------------------------------------------------------------
 Hash Join  (cost=29.35..53.63 rows=1130 width=44)
   Hash Cond: (c.user_id = u.user_id)
   ->  Seq Scan on comments c  (cost=0.00..21.30 rows=1130 width=44)
   ->  Hash  (cost=18.60..18.60 rows=860 width=4)
         ->  Seq Scan on users u  (cost=0.00..18.60 rows=860 width=4)
(5 rows)

cost=29.35..53.63 -> estimated cost(startup and total)
rows=1130 -> estimated rows
width=44 -> estimated width
Hash cond -> condition that is being used for matching
Seq scan: Reads a table sequentially
